# VJSOS Company — Core Values

> The 7 operating principles that guide every decision.

## 1. Build Capability Before Buying Capacity

**Statement:** Skills, systems, and documentation come before hardware, hires, and spend.

**Why:** Capital-efficient. We prove a workflow on current resources before investing to scale it.

**Behavior:** When tempted to buy a new workstation or hire, first document and improve the existing process. Upgrade hardware only when Phase 3 work genuinely blocks revenue.

## 2. Originality Is Law

**Statement:** Everything VJSOS creates — characters, stories, code, music, scripts — is original, licensed, public-domain-confirmed, or created in-house.

**Why:** Protects IP, avoids legal risk, and builds a unique brand.

**Behavior:** Every asset is rights-checked. No "confusingly similar" designs to existing IP. See [[prompts/RIGHTS_CLEARANCE]].

## 3. Child Safety First

**Statement:** Children's content is governed by a non-negotiable safety gate.

**Why:** The audience's welfare and our reputation depend on it. Regulatory and trust reasons.

**Behavior:** Every kids episode passes the [[prompts/CHILD_SAFETY]] review (step 19/22) before publishing. No dangerous imitation, no fear tactics, no privacy risk.

## 4. Trust Over Virality

**Statement:** We grow through evergreen, trust-based content — not through manipulative engagement hacks.

**Why:** Sustainable growth and long-term reputation beat short-term spikes.

**Behavior:** Titles promise one thing and deliver it. Thumbnails are truthful. We study what works and improve clarity, not clickbait. See [[docs/KIDS_STUDIO]] packaging rules.

## 5. Phase-Aware Development

**Statement:** Work is classified by capability (Phase 1–4); we always do Phase 1–2 before Phase 3, and defer/outsource Phase 4.

**Why:** Realistic timelines, managed technical debt, capital efficiency.

**Behavior:** Every task is tagged with a phase. We never block delivery on a Phase-4 requirement the current hardware can't meet.

## 6. Systems Before Heroes

**Statement:** A documented system beats an individual hero. We build for repeatability, not individual brilliance.

**Why:** Systems scale; heroes burn out. Documentation-as-code means anyone (or any agent) can execute.

**Behavior:** All workflows are captured in SOPs and prompts. Knowledge is versioned in Git. See [[governance/DocumentationRules]].

## 7. Knowledge Is Compound Interest

**Statement:** Every document, decision, and lesson compounds into a better organization.

**Why:** The knowledge base is a permanent asset that grows in value the longer we invest in it.

**Behavior:** Session logs daily, ADRs for decisions, retrospective lessons captured. One small improvement compounding beats occasional big sprints.

## How We Apply These

- Conflict? Higher-number value wins only with explicit CEO reasoning.
- All new agents and hires are grounded in these values.
- The immutable versions live in [[kernel/CorePrinciples]].
