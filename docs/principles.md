# VJSOS Operating Principles

## Core Principles

### 1. Build capability before buying capacity
Hardware and budget should **accelerate a working system**, not replace one.
- Fix the business first, validate the idea, improve the pipeline.
- Upgrade hardware only when it becomes a genuine bottleneck, not because it's available.

### 2. Phase-wise capability
Not all work is equally hard. We classify effort into phases and work within our current stack:
- **Phase 1:** Brain-layer work (planning, docs, Obsidian, Git, research) — 100% possible
- **Phase 2:** Core software (Python, React, Electron, Android) — 90% possible
- **Phase 3:** Creative + AI (Blender light, Remotion, image gen, 7B LLM) — possible but slow
- **Phase 4:** Heavy production (high-quality 3D, 4K, 30B+ models, training) — not practical yet

### 3. Phase-bound work
Every task is classified by phase. We prefer Phase 1→2 work; Phase 3 work is intentional and slow; Phase 4 work is deferred or outsourced.

### 4. Validation before investment
Before major hardware purchases or outsourcing:
- Validate the idea
- Improve the pipeline
- Then invest to scale

### 5. Evergreen over viral
Channel strategy: target **evergreen demand** and **real audience problems** rather than chasing viral trends.

### 6. Child safety is non-negotiable
All kids content passes a dedicated child-safety review. No scary imagery, unsafe imitation, privacy risks, or manipulative engagement.

### 7. Originality is law
No derivative IP. Everything original, licensed, or rights-cleared. We take inspiration broadly but never copy distinctive expression.

## Decision-Making Rules

| Situation | Rule |
|-----------|------|
| Task classification | Classify by phase (1-4). Can't do Phase 4? Do Phase 1-2 version or defer |
| Hardware upgrade | Only after Phase 3 work blocks revenue/capacity |
| New business unit | Must map to a known channel niche (see [[ANDROID_CHANNEL]], [[KIDS_STUDIO]]) |
| Content packaging | Title = one promise; Thumbnail = outcome/problem; First 5-10s match title |
| Team scaling | Hiring comes after systems are documented and reproducible |
